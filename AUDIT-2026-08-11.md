## 1. Polaroid — Double Polaroid feasibility

### Blocking schema fact

```sql
create table public.polaroids (
  day date not null unique,       -- ← ONE photo per day for the COUPLE
  image_path text not null,
  taken_by uuid not null default auth.uid(),
  ...
);
```

`day` is `unique`, and `useUpsertPolaroid` upserts `onConflict: 'day'`. **Whoever shoots second overwrites the first.** Today the couple shared one slot; that's exactly why it "worked" while together.

Double Polaroid requires: `unique (day, user_id)` and every read/write scoped per member. This is a migration + a rewrite of `polaroid.queries.ts` / `.mutations.ts` / route. Existing rows must be backfilled with `user_id = taken_by` (the column already exists, so **no data is lost**).

### The timezone question (the interesting part)

- `todayKey()` in `polaroid/types.ts` uses **device local time** — so Vicente's "today" and Anastasia's "today" are different strings for ~11 h a day. Two different rows, correctly.
- There is already a correct primitive for the _shared_ day: `kernel/lib/couple-day.ts → coupleDay(selfZone, partnerZone)` = MIN of both civil dates, unit-tested.
- **But for the Double Polaroid the right model is the opposite of `coupleDay`:** each person's photo is keyed to _their own_ civil date (`day` in their own zone), and the pairing is `day == day`. Anastasia's Sunday photo pairs with Vicente's Sunday photo, even though she took hers ~11 h before he woke up. That is exactly what the user described, and it needs **no offset math at all** — just per-user local day keys and a join on the date string.
- Consequence to be explicit about: for ~11 h, Anastasia's "today" row exists while Vicente's "today" row cannot yet be created. The UI must show her card as _filled_ and his as _waiting for tomorrow-for-him_ without reading as "missing". Design problem, not a data problem.

### Performance — why old polaroids are slow (root cause confirmed)

1. **`useProxiedUrl` fires TWO `createSignedUrl` calls per photo** — one for `thumbs/<path>`, one for the full original — _even in the gallery where only the thumbnail is ever displayed_. N photos = **2N HTTP round-trips**, each ~100–300 ms.
2. **No batching.** Supabase exposes `createSignedUrls` (plural, one request for many paths). It is used nowhere in the codebase.
3. **No pagination.** `usePolaroids()` does `select('*')` over the whole table and `Gallery` renders **every** past photo as a full-width `<img>`. At 100+ days this is 200 signed-URL requests on mount.
4. **CacheWarmer preloads serially** — `for (const path of …) { await createSignedUrl(…) }` for 24 photos, one after another, ~24 sequential round-trips.
5. `loading="lazy"` is set on the `<img>`, but the _signed URL request_ is not lazy — it fires from the React hook the moment the component mounts, so lazy loading buys nothing.
6. SW image cache (`katitos-img-v1`) is correct and token-agnostic — that part is good; it only helps on the **second** view.

Yes, proxies exist and are correct (WebP, 400 px, `thumbs/` tree, graceful fallback). The proxy _bytes_ are fine. **The bottleneck is URL signing, not image size.**

## 3. Albums — multi-album

The 3D book engine is **already the right shape**:

```
album_books (id, scope 'life'|'trip', trip_id, title)
  └ album_pages (book_id, position)
      └ album_photos (page_id, slot, image_path, caption, source, x, y, scale, rotation)
```

`album_photos` already supports free-positioned stickers (x/y/scale/rotation, normalized 0..1), three sources (`upload | polaroid | text`), and the slot grid check was already dropped.

What blocks "many albums":

- `album_books_life_uniq` — a **partial unique index allowing exactly one** `scope='life'` book.
- `album_books_trip_uniq` — one book per trip.
- `useBook(scope, tripId)` resolves a book by _scope_, not by id. No list route, no cover, no create/rename/delete.
- No date range, cover image, or ordering on `album_books`.

So: drop the two unique indexes, add `slug/cover_path/started_on/ended_on/position`, add an album-list route + create flow, change `useBook` → `useBookById`. The whole flip engine, geometry (unit-tested `book-geometry.ts`), sticker drag, text stickers and page seeding carry over untouched.

**Legacy sticker album still exists** (`album_chapters / album_slots / album_stickers` + `useStickSticker`, `progression.ts`, `AlbumWidget`). `album.route.tsx` no longer renders it — only the progress widget reads it. Dead weight to either delete or repurpose.

Known rough edges in the book (user already knows it's "buggy"): the `turnToPage` re-sync on every `pages` change is a known StPageFlip fight; the arrange-mode editor and the read-mode book are two separate render paths.

## 4. Currency

### Bug A — duplicated code (confirmed)

`formatMoney()` uses `Intl.NumberFormat({style:'currency'})` → returns **`"CLP 123.4"`** (code prefixed). Then `currency.route.tsx` renders:

```tsx
{
  resultText;
}
<span className="text-2xl text-accent">{to}</span>;
```

→ **`CLP 123.4 CLP`**, second one gold/right. Exactly as reported. Fix: format the _number only_, put the code after it.

### Bug B — forced decimals

`minimumFractionDigits: 1, maximumFractionDigits: 1` on everything. CLP and RUB are whole-unit currencies; `123.4 CLP` is wrong-looking. Should be per-currency decimals (CLP/RUB/GEL → 0, USD/EUR/TRY → 2 or smart).

### Gap C — EUR missing

Absent from: `currencies.ts` (the bench), `settings.route.tsx` (its own duplicated hardcoded list — **two sources of truth**), `cache-warmer.ts` `RATE_CODES`, the `currency-rates` edge function's `CURRENCIES`, and every seed migration.

### 🔴 Trap D — adding EUR would silently not work

`refreshRatesIfStale()` decides whether to refresh by looking at the **oldest existing row's** `fetched_at`:

```ts
if (age < RATE_STALE_MS) return; // 8h
```

Add `'EUR'` to `RATE_CODES` and _no EUR rows exist yet_ — but if the existing 20 rows were refreshed <8 h ago, the guard returns early and **EUR never gets fetched**, possibly for days. The staleness check must also detect **missing pairs** (expected pair count vs actual), not just age. (Same class of bug as the `d12db8f` newest-vs-oldest fix.)

### Missing feature — always-visible cross rates

Requested: when neither side is RUB nor CLP, show small secondary conversions (e.g. GEL→EUR shows a mini "in CLP" left and "in RUB" right) between the numpad and the amounts. `convert()` already triangulates via USD, so the data is there — this is pure UI.

### Minor

- `freshness()` and `updatedAt` compute from `Math.max(fetched_at)` — a single fresh row makes a whole stale table look current.
- No manual refresh gesture.
- The `currency-rates` edge function still lists only `USD/CLP/RUB/GEL` (no TRY, no EUR) and is **still not on any schedule** — the client-side `refreshRatesIfStale` is what actually keeps rates alive.

## 5. The Wall — slow background (root cause confirmed)

```ts
// vite.config.ts
injectManifest: {
  globPatterns: ['**/*.{js,css,html,svg,png,woff2}'];
}
```

**`jpg` is not in the list.** `public/chalkboard.jpg` is **150 KB** and is referenced only as a CSS `background-image` inside `chalkboard.route.tsx` — which is a **lazy-loaded route chunk**. So the chain on every cold visit is:

route tap → download route JS chunk → React renders → browser _discovers_ the `url(/chalkboard.jpg)` → 150 KB network fetch → paint.

Nothing preloads it, nothing precaches it, and it isn't in the SW shell cache. That is the 2–3 s.

Fixes available (stackable): add `jpg,jpeg,webp` to `globPatterns`; convert to WebP/AVIF (~40–60 KB); add `<link rel="preload" as="image">` in `index.html`; inline a tiny blurred base64 LQIP as the immediate background so the slate is never empty. Note there's an untracked `grunge-style-blackboard-texture.jpg` in the repo root — presumably the intended replacement.

Also on the Wall:

- `onTransform` fires **two** mutations (`useResizeNote` + `useRotateNote`) = 2 writes + 2 invalidations per pinch. Should be one update.
- `chalkboard_notes` **is** in the realtime publication ✅.

## 7. Wishlists — needs a redesign, not a fix

Currently: create a list → add items → **swipe left/right like Tinder** → items both liked appear in a "Matches" tab. That is a _decide-together_ tool. What's wanted is a **gift registry per person**.

Schema (usable, incomplete):

```sql
wishlists      (id, title, category, description, created_by)
wishlist_items (id, list_id, title, description, image_path, link, added_by)
wishlist_votes (item_id, user_id, vote -1|1)
```

- `image_path` exists but **nothing ever writes or reads it** — no upload, no display.
- No "this list is _for_ whom" column — the gift model needs `owner_user_id` (a list for Katita, a list for Katito).
- No `price` / `currency` / `priority` / `bought` / `reserved` — a gift list wants at least "got it already", ideally hidden from the recipient.
- **No edit** for a list or an item (create + delete only).
- No sort/reorder, no image, no thumbnails.

Performance shape (matters given "fast as fuck"):

- `LoadingScreen` blocks the entire route while items load — no skeletons, no optimistic writes anywhere in the feature.
- No optimistic mutations: every add/delete waits for the server round-trip then a full invalidate + refetch.
- **`wishlists`, `wishlist_items`, `wishlist_votes` are NOT in the `supabase_realtime` publication** → all three `useTableSync` calls in the routes register but **never fire**. Silent dead code today.
- Query defaults are `staleTime 30 s` + `refetchOnWindowFocus: false`, and the localStorage persister (`kernel/query/persist.ts`) is already in place — so instant-paint-then-revalidate is achievable cheaply.

`home.route.tsx → loveNotes(name, g)` gender-matches _some_ strings (`любимая/любимый`, `polola/pololo`, `bonita/bonito`) but hardcodes **feminine-only** ones into the shared pool:

```
'Liubimonkeykaya 🥰', 'Liubimonkeykayita 💞', 'любиминки 🤍'
```

These are picked at random for **either** partner. That's the "she sends me Liubimaya" report.

### Missing vocabulary

Not present anywhere: **Katito / Katita / Katitos / Cutetitos**, Polar bear, "Panda" (the plush), the robot-tulas joke, the marriage line, the _Katito Katito my wonderful Katito · tuturututu…_ song.

### No way to add/edit phrases

The pool is a hardcoded array inside a React component. Requested: an editor in Settings, **owner-only** (Vicente). There is no admin/owner concept in the codebase at all today — the closest is `couple_members.role = 'a' | 'b'`. Phrases would want their own table (`love_phrases`: text, gender `m|f|any`, weight, enabled) so they sync across devices instead of living in localStorage.

### 🔴 Notifications are globally muted

`kernel/push/notify.ts`:

```ts
const ALLOW_ONLY_LOVE = true; // suppresses EVERY non-'love' push
```

Wall notes, album stickers, Know-Me, tree — all their `notifyPartner` calls return `{ok:true, delivered:0}` and send nothing. Also `useAddNote` and `useStickSticker` call `notifyPartner` **without** `kind`, so they're silently dropped.

Other push facts:

- Push send-path itself is sound: the edge function resolves the partner server-side and refuses arbitrary targets ✅, prunes dead 404/410 subscriptions ✅, `useEnsurePushSubscription` re-persists on every launch ✅.
- Notification payload has **no `actions`, no `image`, no `renotify`, no vibration pattern, no per-kind `tag`** — every push looks identical on the lock screen.
- `notificationclick` navigates an existing window ✅.
- **Prod VAPID keys are still unverified** (flagged in the June audit, never closed). Worth confirming with a real send before relying on it across 11 time zones.

## 10. Flowers — rebuild

Existing feature is nothing like the request. Current: `flowers(occasion_date unique, image_path, note, given_by)`, route = **2-column CSS grid of cards** (violates the no-grid taste rule), camera-only capture (`CameraCapture`, no gallery, no crop), free-form date input, anyone can add or delete, no year sections, no month labels.

Requested: year sections → **3-column square polaroids**, month caption (`Apr 2026`), her-only upload (with a restorable dev override), crop/resize to square on upload, normal mode shows only filled months, edit mode shows all 12 slots of the year.

What's missing in the codebase to build it:

- **No image cropper anywhere.** `CameraCapture` centre-crops to square automatically but only from the live camera; `FilePickerButton` exists but has no crop UI. A pan/zoom square cropper is a new kernel component (the gesture stack — `@use-gesture/react` + the polaroid viewer's pinch/pan math — is already there to borrow from).
- **No permission/role gating primitive.** Needs something like `couple_members.role === 'b'` checks plus a dev override flag.

- Flowers uses `useSignedUrl` (full-size) not `useProxiedUrl`, and `useUpload` not `usePhotoUpload` → **no thumbnails are generated for flowers at all**. A 3-column year grid would download full-res photos. Must move to `usePhotoUpload` + proxies.

## 13. Cross-cutting findings (not asked for, worth fixing)

1. **Realtime publication is incomplete.** In the publication: `app_opens, couple_members, chalkboard_notes, polaroids, scavenger_cards, scavenger_claims, deck_responses, know_me_days, know_me_presence, language_decks, tree_*, trip_legs, album_slots, album_stickers, album_books, album_pages, album_photos`. **Missing but subscribed-to in code:** `wishlists`, `wishlist_items`, `wishlist_votes`, `flowers`, `phrases`, `dates`. Those `useTableSync` calls are dead.
2. **RLS is member-gated but not author-gated.** Nearly every table is `for all using (is_member()) with check (is_member())` — either member can write rows attributed to the other (`created_by`/`user_id` default to `auth.uid()` but nothing enforces it on UPDATE). Low risk for two people; it _does_ matter for the new "her-only Flowers upload" and "owner-only phrase editing".
3. **No couple bootstrap.** Still no `handle_new_user` trigger; the rows were inserted by hand. Fresh deploy = empty app.
4. **`storagePaths.polaroid`** is dead and its comment ("one per day → overwrite") is now actively misleading given versioned paths.
5. **Two hardcoded currency lists** (`currencies.ts` and `settings.route.tsx`).
6. **`widgets.registry.ts`** still entirely unused (flagged June, still there).
7. **`scavenger_arguments`** table has no code path at all.
8. **`useRotateNote`** is only used alongside `useResizeNote` — should be merged.
9. **Bundle**: `manualChunks` splits react/supabase/query/vendor ✅, routes are lazy ✅. But **Leaflet (`leaflet` + `@types/leaflet`) is only used by Summer's map tab** — retiring Summer should drop the dependency entirely.
10. **`novat.png` is 290 KB** and loads on Home unoptimized (no WebP, no `width`/`height`, no `fetchpriority`).
11. **Query persister** dehydrates _every_ successful query into one localStorage blob — with a large polaroid list + signed URLs this will approach the ~5 MB quota and then silently drop the whole snapshot (`catch → removeItem`). Signed URLs shouldn't be persisted at all (they expire in 1 h).
12. **`polaroids` and other tables have no index on `day`** beyond the unique constraint — fine now, but per-user pagination will want `(user_id, day desc)`.
